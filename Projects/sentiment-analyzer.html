The Problem & Core Idea

Determining the sentiment of unstructured text — whether a given sentence, review, or message expresses positive, negative, or neutral emotion — is a foundational Natural Language Processing (NLP) task. Manual classification doesn't scale, and building a model from scratch requires significant ML expertise.

This project implements a complete sentiment analysis pipeline: from text preprocessing with stopword removal, through SVM model training on a custom dataset, to a deployable Streamlit web interface where users can enter any text and get instant sentiment predictions.

Key Capabilities

Real-Time Prediction

Users enter any text and receive instant sentiment classification — no batch processing or delays.

Custom Dataset Training

The SVM classifier is trained on samples.csv, a custom dataset with labeled sentence-sentiment pairs.

Modular Architecture

Clean separation of concerns: training.py handles model training, app.py serves the web UI, and utils.py provides preprocessing helpers.

Persistent Model Artifacts

Trained model (sentiment_model.pkl) and fitted TF-IDF vectorizer (vectorizer.pkl) are saved for production inference without retraining.

Technical Pipeline

Text Preprocessing

Stopword removal and text normalization applied to raw input text before vectorization, ensuring consistent feature representation for the classifier.

Feature Extraction

TF-IDF (Term Frequency-Inverse Document Frequency) vectorizer converts preprocessed text into numerical feature vectors consumable by the SVM model.

SVM Classification

A Support Vector Machine classifier trained on labeled sentiment data predicts whether input text is Positive, Negative, or Neutral.

Streamlit Deployment

The trained model and vectorizer are loaded at runtime in a Streamlit web app, providing a clean UI for users to input text and see predictions.

Engineering Challenges & Solutions

Challenge 1: Noisy Text Normalization

Natural language input contains punctuation, inconsistent casing, and irrelevant stopwords that degrade model accuracy. Implemented a standardized preprocessing pipeline in utils.py that lowercases, removes punctuation and stopwords, and normalizes text before TF-IDF vectorization.

Challenge 2: Model Persistence & Reload

Re-training the SVM model on every app launch is computationally expensive. Solved by serializing both the trained classifier and the fitted vectorizer to pickle files (.pkl) during training, which are then deserialized at app startup for instant inference.
