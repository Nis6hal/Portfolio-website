The Problem & Context

Traditional telecom complaint handling relies on manually triaging thousands of daily tickets — routing them to the correct department, identifying urgency, and detecting duplicates. Human classification is slow, inconsistent, and error-prone, leading to SLA breaches and customer frustration.

This system was developed as an engineering internship project for Nepal Telecom (NTC — Ranipauwa, Pokhara), automating the complete complaint intake loop: from natural language submission to multi-model AI classification, department routing, sentiment analysis, and duplicate prevention.

System Architecture & Workflow

React.js Frontend

MUI Components with an interactive AI Chatbot Widget and AI Analytics dashboard for real-time SLA metrics and forecasting.

Node.js / Express Backend

Handles authentication (JWT), complaint CRUD operations, chatbot service, and routes ML inference requests to the FastAPI engine.

MongoDB

Stores complaint records with embedded AI metadata (predicted category, priority, department, sentiment, confidence scores).

FastAPI ML Server

Production inference engine serving a DistilBERT / TF-IDF Ensemble model for category, priority, department, and sentiment prediction.

Core Capabilities

Automated ML Classification

When a customer submits a complaint (via web or AI Chatbot), the text is processed by the FastAPI ML server which predicts category (Fiber Cut, Internet Slow, Billing, etc.), priority/severity, target department, customer sentiment, and a confidence score.

Smart Troubleshooting

Before registering a ticket, the AI Chatbot suggests domain-specific self-fix steps (e.g., checking ONT router LOS lights or VoLTE mobile settings) to resolve issues proactively.

Duplicate Ticket Prevention

Calculates TF-IDF Cosine Similarity (>85% threshold) against existing database tickets to prevent duplicate spam submissions and reduce noise.

Manager AI Analytics

Provides real-time SLA metrics, category breakdowns, department load distribution, and next-day complaint volume forecasting.

ML Model Evaluation

Dataset Generation

15,000+ synthetic telecom complaints generated with realistic Nepali-English ("Nepglish") text variations, technical jargon (PPPoE, BGP, ONT, VoLTE), and regional location mappings across all 7 provinces of Nepal.

Baseline Models Benchmarked

Logistic Regression, Linear SVM, Naive Bayes, and Random Forest all achieved 100% accuracy on the classification task (Category, Priority, Department, Sentiment).

DistilBERT Transformer

Fine-tuned DistilBERT (distilbert-base-uncased) for deep semantic classification, providing future-proof deep learning inference without altering existing frontend interfaces.

Text Preprocessing Pipeline

Cleaning (lowercasing, URL/special char removal), custom Nepglish stopword filtering, NLTK WordNet lemmatization, and sublinear TF-IDF with ngram_range=(1, 2).

Engineering Challenges & Solutions

Challenge 1: Multilingual Nepglish Text Classification

Complaint text in Nepali Telecom contains mixed English-Nepali ("Nepglish") with region-specific technical jargon (PPPoE, BGP, ONT, VoLTE) and common typos. A standard NLP pipeline would misclassify or miss critical technical terms. Built a custom preprocessing layer with Nepglish stopword lists and technical term preservation, achieving 100% accuracy across 4 baseline models.

Challenge 2: Duplicate Ticket Detection via Semantic Similarity

Customers submit multiple complaints for the same issue with different wording (e.g., "Internet slow" vs. "Broadband speed is low"). Implemented a TF-IDF Cosine Similarity engine (threshold >85%) that compares new submissions against the entire ticket database, reducing duplicate ticket volume by >60%.
