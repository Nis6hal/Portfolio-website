ReadLib — Local-First Book Management System

A private, local-first library and personal reading companion with an embedded PDF document reader, persistent offline IndexedDB storage, and reading progress tracking.

The Problem & Core Idea

Most contemporary book and document management tools force users into cloud accounts, subscriptions, and proprietary file locking. If your internet connection drops or the service shuts down, your library is inaccessible.

ReadLib was built on the Local-First software principle: your books, PDFs, and reading progress stay permanently on your machine inside IndexedDB. The app loads instantly even with zero internet connectivity.

Key Features

Embedded PDF Reader

Read uploaded PDF books directly inside the browser using Mozilla's pdf.js engine with zoom controls, page jumps, and dark reading mode.

Reading State Tracking

Organize books into To Read, Currently Reading, and Completed shelves with automated page bookmark persistence.

IndexedDB Binary Storage

Stores raw PDF binary blobs and generated cover thumbnail caches client-side without hitting 5MB LocalStorage limits.

Import & Export Backup

One-click JSON export and import allows users to migrate their complete reading catalog to other devices seamlessly.

Engineering Challenges & Solutions

Challenge 1: Large PDF File Memory Pressure in Browser

Loading multi-hundred-megabyte textbooks into standard JavaScript memory can crash mobile browser tabs. Solved by streaming PDF byte arrays in chunks using pdf.js Range requests rather than loading entire blobs into RAM at once.

Challenge 2: Client-Side Cover Thumbnail Extraction

To avoid manual cover uploads, an automatic pipeline renders page 1 of every ingested PDF onto a hidden HTML5 canvas, converting the rasterized frame to a lightweight WebP thumbnail stored alongside metadata.

IndexedDB Storage Schema

ReadLib uses a small but carefully designed object store layout inside IndexedDB. Each store handles a distinct domain, and relationships are maintained through explicit foreign keys rather than nested embeddings.

Books Store

Primary key is a UUID. Stores title, author, metadata, shelf status, and a foreign key pointer to the binary blob store for the PDF file.

Blobs Store

Stores raw PDF binary data and generated WebP cover thumbnails keyed by book ID. IndexedDB handles multi-megabyte blobs far better than localStorage.

Reading Progress Store

Tracks per-book state: current page, zoom level, last read timestamp, and shelf assignment (To Read, Currently Reading, Completed).

Settings Store

App-level preferences such as theme, reader font size, and sidebar layout, persisted locally so they survive page reloads and app updates.

Import / Export & Data Portability

A core principle of the local-first approach is that users should own their data. ReadLib provides a one-click JSON export that serializes the entire catalog — metadata, progress, and shelf assignments — into a single downloadable file.

JSON Snapshot Export

Exports all book metadata and reading progress into a portable JSON file. Raw PDF binaries are excluded from the snapshot since they are too large for text-based formats.

Catalog Rehydration

Importing a previously exported JSON snapshot rebuilds the complete reading catalog on a new device without requiring a server account or manual re-entry.

Zero Cloud Dependency

All export and import operations run entirely client-side. No data ever leaves the device unless the user explicitly initiates a transfer.

Lessons Learned & Outcomes

The local-first architecture taught me that offline capability is not an afterthought but a design constraint that shapes every decision. Streaming large PDFs safely required rethinking how browsers handle memory, and the custom thumbnail pipeline proved that even complex media processing can run client-side when done incrementally.

ReadLib demonstrates that privacy-respecting, fully offline applications are not only possible but can deliver a polished, performant reading experience without any server dependency.
